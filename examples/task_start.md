# タスク開始時の報告例

タスクを開始する際の音声報告の例です。

## 基本的な開始報告

**重要**: 「タスク」「作業」「処理」などの抽象的な表現は避け、具体的な作業内容を述べます。

```bash
vp "ビルドを開始します"
vp "テストを実行します"
vp "デプロイを開始します"
vp "コンパイルを開始します"
vp "データベースマイグレーションを開始します"
```

## より詳細な開始報告

```bash
vp "フロントエンドのビルドを開始します"
vp "ユニットテストを実行します"
vp "本番環境へのデプロイを開始します"
vp "タイプスクリプトのコンパイルを開始します"
```

## 技術用語をカタカナ変換した例

| 英語 | カタカナ表記 | 使用例 |
|------|------------|--------|
| build | ビルド | `vp "ビルドを開始します"` |
| test | テスト | `vp "テストを開始します"` |
| compile | コンパイル | `vp "コンパイルを開始します"` |
| deploy | デプロイ | `vp "デプロイを開始します"` |
| install | インストール | `vp "インストールを開始します"` |
| migration | マイグレーション | `vp "マイグレーションを開始します"` |
| Docker | ドッカー | `vp "ドッカーコンテナを起動します"` |
| server | サーバー | `vp "サーバーを起動します"` |

## 長時間かかる処理の開始報告

```bash
vp "大規模ビルドを開始します"
vp "全テストスイートを実行します"
vp "データベースのバックアップを開始します"
```

## 使用上の注意

- **オプションは使用しない**: `vp "メッセージ"`の形式のみを使用
- **1文で簡潔に**: 開始報告は1文で簡潔に（10〜20文字程度が理想）
- **具体的な内容を含める**: 「タスク」「作業」「処理」などの抽象的な表現は避ける
- **事実を淡々と述べる**: 感情表現は不要。起きた事実のみを報告
- ユーザーがすぐに内容を理解できるように
- 英語の技術用語は必ずカタカナに変換
